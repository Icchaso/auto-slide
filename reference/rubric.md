# SlideSmith 採点表（ルーブリック）

> 目的: スライドを「測る → 点をつける → 直す」を、どのモデルでも同じ基準で回すための表。
> 2026-09 作成。スライドデザインの定番文献・研究（SlideGen / PPTAgent / AutoPresent ほか）とWCAGを元にまとめた。閾値の多くは「推計」なので、合格/不合格の実例で随時較正する。

## 使い方（誰が何を見るか）

| 段 | 誰が | 見るもの |
|---|---|---|
| 機械検品 | `scripts/qc.mjs`（自動） | 印 **[機械]** の項目。`out/qc-report.json` の error が0になるまで直す |
| 見た目レビュー | **作り手とは別のエージェント**（`reference/reviewer.md` の手順） | 印 **[目視]** の項目。描画後のPNGだけを見て採点する |

- 各項目 **0 / 1 / 2 点**（2＝満たす、1＝惜しい、0＝満たさない）
- **【GATE】** は0点なら他が満点でも不合格
- 機械検品で既に保証される項目（はみ出し・最小文字・コントラスト等）は、レビュー役は採点しない

## よくある不合格の型 — 最優先で避ける

| よくある指摘 | 実際に起きていたこと | 対応する項目 |
|---|---|---|
| 「シンプルすぎる」 | 整っているだけで図も強弱も無い | D9 図解率 / P各項目の「ジャンプ率」「専用感」 |
| 「スカスカ・読みにくい」 | 余白が多すぎる・文字が小さく薄い・単調・泣き別れ | BOTTOM_EMPTY / FONT_SMALL / CONTRAST / D6〜D10 / J4 |
| 「素人っぽい」 | 空の画像枠・見出しが途中で切れる・白×カード型ばかり | IMG_BROKEN / TITLE_FRAGMENT / D8 / D10 |

既定の好み（依頼者の好みが分かっていればそちらを優先）: 躍動感のあるゴシック系。明朝・和風は依頼が無ければ使わない。「プロ級」＝①図解力 ②ジャンプ率（巨大な主役と極小の脇役）③レイヤー感 ④この資料専用に作った感（バッジ・注釈）⑤英字マイクロキャプション等のディテール。

## 機械検品のコード一覧（qc.mjs）

| コード | 重さ | 意味 |
|---|---|---|
| IMG_BROKEN | error | 画像が表示されていない（空の枠） |
| TITLE_FRAGMENT | error | 見出しが文の途中で終わっている |
| TITLE_TOO_LONG | error | 見出しが3行以上 |
| OUT_OF_SLIDE / BOX_OVERFLOW / TEXT_OVERLAP | error | はみ出し・枠あふれ・文字の重なり |
| FONT_TINY | error | 18px未満の文字 |
| LOW_CONTRAST | error | 本文4.5:1未満／大きい文字・注釈3:1未満 |
| BOTTOM_EMPTY | error | 本文系の型で下1/3が空 |
| PLACEHOLDER | error | 置き忘れの仮テキスト |
| LAYOUT_REPEAT | error | 同じ型が3枚連続 |
| CARDS_DOMINANT | error | カード並べ系が本文の50%超 |
| VISUAL_SHORTAGE | error | 図解・写真・巨大数字が主役の枚が本文の40%未満 |
| IMG_DISTORTED | error | 画像の縦横比の歪み |
| FONT_SMALL / CONTRAST_WEAK / CAPTION_FAINT | warn | 本文28px未満（目標36px）／本文7:1未満／注釈が薄い |
| BOTTOM_SPARSE / SPARSE / HOLLOW_BOXES | warn | 下の余白広め／全体スカスカ／枠の中が空き気味 |
| TITLE_SOFT_END / TITLE_ORPHAN | warn | 助詞終わり（意図なら「。」）／最終行2文字以下 |
| LOW_JUMP | warn | 文字の大小差1.5倍未満 |
| CARDS_MANY / VISUAL_LOW / LAYOUT_DOMINANT / LOW_VARIETY | warn | カード25%超／図解60%未満／1型30%超／種類不足 |
| NO_DARK / FLAT_RHYTHM / FONT_SCALE_MESSY | warn | 暗面ゼロ／同じ明るさ6枚連続／文字サイズ種類過多 |
| IMG_LOWRES | warn | 画像の解像度不足 |

## 単位換算（数値の土台）
PowerPoint 16:9 標準は 960×540pt。1920×1080px で組むので **1pt＝2px**。本文の目標36px（18pt）、注釈の下限24px（12pt）。

### P01 表紙

- **目的**: 何の資料で、誰に向けた、誰からの提案かを1秒で伝え、期待を上げる
- **必須要素**: タイトル（ベネフィットを含む）／サブタイトル（対象・文脈）／提案者名・ロゴ／日付／キービジュアル（写真・図形・パターン）
- **合格基準**
  1. [機械]【GATE】タイトル文字サイズ ≥ **96px**（本文最小36pxの約2.7倍以上）
  2. [機械] タイトル ÷ 最小文字（日付・社名） ≥ **4**
  3. [機械] タイトルは **2行以内・40字以内**
  4. [目視] タイトルが「〇〇のご提案」だけでなく、相手の得（ベネフィット）が読める
  5. [機械] キービジュアル（img/svg/装飾図形）がスライド面積の **30%以上**
  6. [目視] 英字マイクロキャプション（例 "PROPOSAL 2026"）等のディテールがある（依頼主の「プロ級」条件⑤）
  7. [機械] 日付・社名が存在する
  8. [目視] 明朝・和風モチーフがない
- **典型的な失敗**: 白背景に中央揃えのタイトルだけ／テンプレ感の強い青い帯／タイトルが長く3行／ロゴが主役より大きい

### P02 アジェンダ・目次

- **目的**: 全体の地図を見せ、今どこかを分からせる
- **必須要素**: 章番号（大きく）／章タイトル（短く）／（任意）各章の1行要約・ページ
- **合格基準**
  1. [機械] 章の数 **3〜6**（Alleyのリスト2〜4項目を目次用に少し緩めた値）
  2. [機械] 章番号の文字サイズ ÷ 章タイトル ≥ **1.8**（番号を図として立てる）
  3. [機械] 章タイトル各 **15字以内**
  4. [機械] 項目間隔が均等（ずれ ±4px）
  5. [目視] 箇条書きの黒丸リストではなく、番号・区切り線・ブロックで構造化されている
  6. [機械] セクション区切りスライドの章タイトルと文字列が完全一致
- **典型的な失敗**: ただの箇条書き／章が8個以上／目次と本編の章名がずれる

### P03 セクション区切り（中扉）

- **目的**: 話の転換を宣言し、デッキに明暗のリズムを作る
- **必須要素**: 章番号（巨大）／章タイトル／（任意）章で答える問い1行
- **合格基準**
  1. [機械] 背景が本文スライドと明確に異なる（背景輝度差 ΔL* ≥ **40**、または全面写真）
  2. [機械] 章番号 ≥ **200px** もしくはスライド高さの **20%以上**
  3. [機械] 文字要素 **3個以内**
  4. [機械] 目次（P02）と章名一致
  5. [目視] 全セクション区切りが同じ型で統一されている（D系の一貫性）
- **典型的な失敗**: 本文と同じ白背景で区切りに見えない／区切りが多すぎる（3枚に1枚など）

### P04 課題提起（問題の列挙）

- **目的**: 聞き手に「それ、うちのことだ」と思わせ、解決策の必要性を作る
- **必須要素**: 課題を総括するアクションタイトル／課題 **2〜4個**／各課題の「影響（損失の数字 or 具体場面）」／（任意）課題同士の関係（原因→結果）
- **合格基準**
  1. [機械] 課題の数 **2〜4**（Alley: リスト2〜4項目、一次）
  2. [機械] 各課題の見出し **20字以内**、補足 **40字以内**
  3. [目視] 少なくとも1つの課題に数字（時間・金額・件数・%）がある
  4. [目視] 課題が並列カードだけでなく、アイコン/イラスト/数字/因果矢印のいずれかで図解されている
  5. [目視] 聞き手の言葉（現場の困りごと）で書かれている
  6. [目視] 最重要の課題が1つ、サイズか色で強調されている（ジャンプ率）
- **典型的な失敗**: 同じ大きさの文章カード4枚（依頼主NGの典型）／課題が抽象的（「非効率」だけ）／課題が7個以上

### P05 主張1つ＋根拠（キーメッセージ）

- **目的**: 1つの結論を強く刻む
- **必須要素**: 主張文（大）／根拠 **1〜3個**（数字・図・出典）
- **合格基準**
  1. [機械]【GATE】主張文の文字サイズ ≥ **72px**、かつ根拠文字の **2倍以上**
  2. [機械] 主張文 **40字以内・2行以内**
  3. [機械] 根拠の数 **1〜3**
  4. [目視] 根拠に数字または出典がある
  5. [機械] 主張文がスライドの上半分〜中央（視線の入口）にある
  6. [目視] 主張文だけ読めば言いたいことが分かる（Glance Test）
  7. [機械] スライド上の総文字数 **120字以内**（Duarte 40語の日本語換算・目安）
- **典型的な失敗**: 主張と根拠が同じ大きさ／主張が「〜について」で結論になっていない／余白ばかりでスカスカ（主張が小さい）

### P06 巨大数字（KPI・実績）

- **目的**: 数字1つで信頼・インパクトを与える
- **必須要素**: 主役の数字（単位込み）／ラベル（何の数字か）／比較基準（前年比・業界平均・導入前）／期間・出典の注釈
- **合格基準**
  1. [機械]【GATE】主役数字 ≥ **200px**（推奨240〜400px）
  2. [機械]【GATE】主役数字 ÷ 最小文字 ≥ **5**
  3. [機械] 主役数字は1スライド **1〜3個**（3個なら1つだけ最大）
  4. [機械] 単位（%・倍・件・円）は数字の **40〜60%** の大きさ（数字を立て、単位を寝かせる。目安・出典弱）
  5. [目視] 比較基準がある（「前年比+32%」「導入前の1/3」等）
  6. [機械] 出典・期間の注釈がある（24〜28px）
  7. [目視] 数字の意味を一言で言う補足（「月40時間の削減」等）がある
  8. [機械] 数字は欧文書体（プロポーショナル or tabular）で、全角数字を使っていない
- **典型的な失敗**: 数字が本文と同じ大きさ／比較がなく凄さが分からない／出典なしで信用されない

### P07 グラフ（棒・折れ線など）

- **目的**: 数量の変化・差を一目で見せ、そこから言えることを示す
- **必須要素**: 「言えること」を書いたアクションタイトル／グラフ本体／直接ラベル／強調系列1つ／単位・出典
- **合格基準**
  1. [目視]【GATE】タイトルがグラフの結論（例「導入後3ヶ月で問合せが2.4倍」）になっている
  2. [機械] グラフ面積がセーフエリアの **50%以上**
  3. [機械] 凡例なし（直接ラベル）、または系列 **2個以下** の場合のみ凡例可（Knaflic, 書籍／Mayer 空間的近接, 一次）
  4. [機械] 目盛線が無い、または線色コントラスト 1.5:1以下の薄さ（Knaflic）
  5. [機械] 強調色の系列 **1つ**、他はグレー（Knaflic）
  6. [機械] 棒・線と背景のコントラスト **3:1以上**（WCAG 1.4.11, 一次）
  7. [機械] 3D・影・グラデーション塗りなし（Tufte データインク比）
  8. [機械] 棒グラフの軸は0始まり（目安・出典弱: 定評あるデータ可視化の慣行）
  9. [機械] 軸ラベル・データラベル ≥ **28px**
  10. [機械] 単位と出典表記がある
- **典型的な失敗**: Excelそのままの既定色・凡例・目盛線／タイトルが「売上推移」／全系列が同じ強さで何を見ればいいか不明

### P08 比較（Before→After、A vs B、表）

- **目的**: 違いを一瞬で分からせ、選ぶ理由を作る
- **必須要素**: 比較の軸（同じ項目で揃える）／左右（または行列）の対比／勝ち側の強調／差分の数字
- **合格基準**
  1. [機械] 比較対象 **2〜3**、比較項目 **5以下**（NN/g 比較表: 5以下に絞る、一次）
  2. [機械] 左右（または列）の同じ項目が同じ高さに揃う（y座標ずれ ±4px）
  3. [目視] Before/Afterなら After 側（推奨側）が色・サイズ・面積で強い（面積比 After ≥ Before × 1.2 など）
  4. [目視] 差分が数字で書かれている（「3時間→20分」）
  5. [目視] 矢印・変化量バッジなど「変化」を示す図形がある
  6. [機械] 表の場合、罫線は横線のみ・細線、セル内余白 ≥ 文字サイズ × 0.5（目安・出典弱）
  7. [機械] 表のセル文字 ≥ 28px、行数 **7以下**
- **典型的な失敗**: 左右が同じ見た目で勝敗が分からない／比較項目が10行以上の表／項目の順番が左右で違う

### P09 プロセス・フロー・ステップ

- **目的**: 手順や流れの順序と全体像を見せる
- **必須要素**: ステップ番号／各ステップ名（短く）／方向を示す矢印・線／（任意）各ステップの所要時間・担当
- **合格基準**
  1. [機械] ステップ数 **3〜5**（6以上なら分割 or 2段）（目安: Alley 2〜4項目＋1）
  2. [機械] ステップ名 **12字以内**、説明 **30字以内**
  3. [機械] 読む方向が1つ（左→右 or 上→下）で、ステップ要素が等間隔（±4px）
  4. [機械] 矢印・コネクタが存在する（カードの単純並べではない）
  5. [機械] ステップ番号がステップ名より大きい or 強調色
  6. [目視] 最重要ステップ（自社が価値を出す箇所）が強調されている
  7. [目視] ゴール（最終状態）が視覚的に区別されている
- **典型的な失敗**: 番号なしカードの横並び（特徴カードと区別がつかない）／矢印が装飾的で方向が曖昧／ステップ8個で文字が小さくなる

### P10 タイムライン・ロードマップ

- **目的**: 時間軸上の予定・実績・フェーズを見せる
- **必須要素**: 時間軸（線）／日付・期間ラベル／マイルストーン／現在地マーカー（ロードマップの場合）
- **合格基準**
  1. [機械] 時間軸の線が存在し、マイルストーンが軸上に配置
  2. [機械] マイルストーン **3〜7個**
  3. [機械] 時間の間隔が距離に比例（等間隔の期間なら等距離、±5%）（目安・出典弱）
  4. [目視] 「今ここ」または「開始/完了」が色で区別されている
  5. [機械] 日付表記の書式が統一（2026年10月 / 2026.10 の混在なし）
  6. [機械] 各マイルストーン説明 **30字以内**
- **典型的な失敗**: 表で書いたスケジュール（時間の長さが見えない）／フェーズ名だけで日付がない

### P11 階層・構造図（ピラミッド、レイヤー、ツリー）

- **目的**: 要素同士の上下関係・包含関係を見せる
- **必須要素**: 階層の段（形で上下が分かる）／各段のラベル／（任意）最上位の強調
- **合格基準**
  1. [機械] 段数 **3〜5**
  2. [目視] 形そのもの（台形・入れ子・ツリー線）で関係が表現され、文字を読まなくても上下が分かる
  3. [機械] 各段ラベル **15字以内**、ラベル文字 ≥ 32px
  4. [目視] レイヤー感（背景→面→注釈の奥行き。依頼主条件③）がある：色の濃淡・重なり・影以外の手段
  5. [目視] ツリーの場合、同じ階層の要素がMECEに見える（重複・抜けがない）
  6. [機械] 同じ階層の要素のサイズ・y座標が揃っている
- **典型的な失敗**: ピラミッドの中に長文を詰めて文字が小さい／階層が図形でなく箇条書きのインデントだけ

### P12 マトリクス（2×2）

- **目的**: 2つの軸で対象を分類し、位置づけ（自社がどこか）を示す
- **必須要素**: 縦軸・横軸のラベル（両端の意味：低⇔高）／4象限の名前／プロットされた対象／自社・推奨象限の強調
- **合格基準**
  1. [機械]【GATE】両軸にラベルと両端の意味がある
  2. [目視] 軸が互いに独立した概念（相関の強い2軸でない）
  3. [機械] 象限の名前が各 **10字以内**
  4. [目視] 推奨象限（通常は右上）が色・面で強調
  5. [機械] プロット数 **8以下**、ラベル重なり0
  6. [機械] マトリクス面積がセーフエリアの **50%以上**
- **典型的な失敗**: 軸の意味が書いてない／4象限に同じ量の文章を詰める／自社がどこか分からない

### P13 ファネル

- **目的**: 段階ごとの減少（歩留まり）とボトルネックを示す
- **必須要素**: 段階名／各段の数値／段間の転換率／ボトルネックの強調
- **合格基準**
  1. [機械] 段数 **3〜6**
  2. [機械] 段の幅が数値に比例（または明示的に「概念図」と注記）
  3. [機械] 各段に実数か%がある
  4. [目視] 段と段の間に転換率（%）が書かれている
  5. [目視] 改善対象の段が1つ強調されている（色・注釈バッジ）
  6. [機械] ラベルがファネル図形の外にはみ出さない／内側で最小文字28px以上
- **典型的な失敗**: 数値なしの飾りファネル／全段同じ色で「どこが問題か」がない

### P14 特徴・メリット3〜4点

- **目的**: 選ばれる理由を覚えやすい数に絞って示す
- **必須要素**: 総括のアクションタイトル／項目 **3〜4**／各項目のアイコン or 画像 or 数字／短い見出し＋1〜2行説明
- **合格基準**
  1. [機械] 項目数 **3〜4**（Alley 2〜4、一次）
  2. [機械] 各見出し **15字以内**、説明 **40字以内**（2行以内）
  3. [目視]【GATE】各項目に視覚要素（アイコン・数字・画像）があり、文章だけのカードでない
  4. [目視] 見出しが「特徴」ではなく「相手の得」になっている（例「24時間自動返信」→「夜間の問合せを取りこぼさない」）
  5. [機械] 各項目のカードのサイズ・位置が揃っている（±4px）
  6. [目視] 最も伝えたい1項目にジャンプ率 or 強調（全部同じは1点止まり）
  7. [機械] このパターンがデッキ内で連続していない（D6/D8と連動）
- **典型的な失敗**: 依頼主NGの本丸＝「白背景＋文章カード3〜4列」が全スライドで繰り返される／見出しが途中で切れる／アイコンが意味と合っていない

### P15 料金・プラン表

- **目的**: 迷わず選べるようにし、推奨プランへ導く
- **必須要素**: プラン名／価格（税込/税抜・月額/年額の明示）／含まれる内容／推奨プランのバッジ／（任意）初期費用・最低契約期間
- **合格基準**
  1. [機械] プラン数 **2〜4**（NN/g: 比較は5以下、一次）
  2. [機械]【GATE】価格に「税込/税抜」と「月額/年額/一括」の表記がある（NN/g: 課金形態を明示、一次。日本では景品表示法・総額表示の観点でも重要＝法解釈は専門家確認）
  3. [機械] 価格の文字サイズ ≥ プラン名 × 1.5、かつ ≥ 56px
  4. [目視] 推奨プランが「おすすめ」バッジ・色付き列・わずかに大きい枠のいずれかで強調（NN/g、一次）
  5. [機械] 比較項目 **7行以内**、各プランで同じ項目が同じ高さ
  6. [機械] ✓/— 等の記号が統一され、記号と背景のコントラスト3:1以上
  7. [目視] 差分（プランで違う部分）が先頭に来ている
- **典型的な失敗**: 全プラン同じ見た目／税込税抜不明／機能行が20行／価格が本文と同じ大きさ

### P16 事例・お客様の声・引用

- **目的**: 第三者の証言で信頼を作る
- **必須要素**: 引用文（短く）／発言者（属性・社名/業種・役職、許可範囲内）／写真 or ロゴ／成果の数字
- **合格基準**
  1. [機械] 引用文 **80字以内**（長い場合は要点を太字で抜く）
  2. [機械] 引用文の文字サイズ ≥ **44px**、発言者情報 ≤ 引用 × 0.5
  3. [機械] 発言者の属性表示がある
  4. [目視] 成果の数字（Before→After）が引用と並んで大きく出ている
  5. [機械] 写真/ロゴ枠が実画像で埋まっている（空枠0）
  6. [目視] 大きな引用符などで「声」であることが一瞬で分かる
  7. [目視] 事例の場合「課題→施策→成果」の3段が揃っている
- **典型的な失敗**: 長文の感想をそのまま貼る／誰の声か不明／写真枠がグレーのまま／成果の数字がない
- **注意**: 医療・治療院関連は体験談・効果表現に医療法（広告規制）・薬機法・医療広告ガイドラインが関わる。原文を確認のうえ、最終判断は専門家（本調査は解釈しない）

### P17 チーム・プロフィール

- **目的**: 「誰がやるか」で信頼を作る
- **必須要素**: 顔写真（統一トーン）／名前／役割／実績の数字 or 資格 1〜3個
- **合格基準**
  1. [機械] 人数 **1〜6**（7以上は主要メンバーだけ or 別ページ）
  2. [機械] 写真のサイズ・トリミング（丸/角）・位置が統一（±4px）
  3. [目視] 写真のトーン（明るさ・背景）が揃っている
  4. [機械] 実績・経歴は1人 **3行以内**
  5. [目視] 1人だけのプロフィールなら写真を大きく（面積25%以上）、数字実績を巨大数字化
- **典型的な失敗**: 写真のサイズ・画角がバラバラ／経歴の長文／顔写真枠が空

### P18 画面スクショ紹介（プロダクト画面の見せ方）

- **目的**: 実際の使用感を見せ、機能の価値を具体化する
- **必須要素**: 画面キャプチャ（端末フレーム or 角丸＋影で浮かせる）／注目箇所の拡大 or 囲み／番号付き注釈（2〜4個）／その画面で得られること（タイトル）
- **合格基準**
  1. [機械] スクショ面積がセーフエリアの **40%以上**
  2. [機械] スクショ内の文字が読めない場合、注目部分の拡大図（ズーム）がある（原寸で24px未満になる部分は拡大必須）
  3. [機械] 注釈 **2〜4個**、番号付き、コールアウトの座標が指す部品の上にある（実測で配置）
  4. [目視] 注釈線・枠が注目部品を正しく指している
  5. [目視] レイヤー感: 背景→スクショ（影/端末）→注釈バッジの3層が見える（依頼主条件③）
  6. [機械] 個人情報・顧客名がスクショに写っていない（ダミーデータ）
  7. [目視] タイトルが機能名ではなく得られる結果を言っている
- **典型的な失敗**: 画面全体を縮小して何も読めない／注釈なしで「どこを見ればいいか」がない／本物の顧客データが写る

### P19 写真全面＋メッセージ

- **目的**: 感情・世界観を一瞬で伝える（デッキのリズムの山）
- **必須要素**: 高解像度写真（全面・裁ち落とし）／短いメッセージ／文字の可読性を確保するオーバーレイ
- **合格基準**
  1. [機械] 写真がスライド全面（面積 ≥ **95%**）
  2. [機械] 写真の実解像度が出力サイズ以上（4K出力なら長辺 ≥ 3840px、最低1920px）
  3. [機械]【GATE】文字直下の領域で文字と背景のコントラスト **4.5:1以上**（オーバーレイ・グラデーションで確保）
  4. [機械] メッセージ **25字以内**、文字サイズ ≥ **80px**
  5. [目視] 写真の主被写体とメッセージが重ならない
  6. [目視] 写真の内容がメッセージと意味的に合っている（ストックフォト感の強い無関係な写真でない）
- **典型的な失敗**: 写真の上に白文字で読めない／低解像度で荒れる／長文を載せる

### P20 Q&A・FAQ

- **目的**: よくある不安を先回りで解消する
- **必須要素**: Q と A の明確な区別（記号・色）／質問 **3〜5**／回答は結論から
- **合格基準**
  1. [機械] 1スライドの Q&A **3〜5組**
  2. [機械] Q **30字以内**、A **80字以内**
  3. [機械] Q と A の書体ウェイトまたは色が異なる
  4. [目視] 回答の1文目が結論（「はい、〜できます」「〜円です」）
  5. [目視] 質問が聞き手の実際の懸念（価格・期間・手間・解約・効果）を突いている
- **典型的な失敗**: 回答が長文で1枚に2組しか入らない／QとAの見分けがつかない

### P21 まとめ

- **目的**: 持ち帰ってほしい要点を固定する
- **必須要素**: 要点 **3つ以内**／各要点は本編のアクションタイトルと対応
- **合格基準**
  1. [機械] 要点 **2〜3**
  2. [機械] 各要点 **30字以内**
  3. [目視] 各要点が本編のどのスライドの結論か追える（新情報を出していない）
  4. [目視] 番号・大きな数字・アイコン等で3点が視覚的に独立している（文章カードだけは1点止まり）
  5. [目視] 次のCTAに自然につながる一言がある
- **典型的な失敗**: 本編の要約を箇条書き10行／新しい話を始める

### P22 CTA・クロージング

- **目的**: 次の行動を1つに絞って促す
- **必須要素**: 行動（動詞で始まる1つ）／方法（URL・QR・連絡先・日付）／期限や特典（あれば）／（任意）不安解消の一言
- **合格基準**
  1. [機械]【GATE】行動の呼びかけが **1つ**（選択肢が3つ以上ない）
  2. [機械] 行動文 **25字以内**、文字サイズ ≥ **72px**
  3. [機械] QRコードがある場合 **一辺 ≥ 240px**（画面越し読み取りの目安・出典弱）かつ周囲に余白
  4. [機械] 連絡先/URLが存在し、テキストとしてコピー可能（PDF出力で文字として残る）
  5. [目視] 行動のハードルが低く具体的（「まずは30分の無料相談」等）
  6. [目視] 「ご清聴ありがとうございました」だけで終わっていない
- **典型的な失敗**: 最後が「ありがとうございました」だけ／問い合わせ先が小さい／行動が複数で迷わせる
